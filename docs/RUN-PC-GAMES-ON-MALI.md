# Running PC games on Mali with PanVK (today)

A concise, practical guide to the current state of running Direct3D PC games on Arm Mali GPUs using PanVK on top of the proprietary `mali_kbase` kernel driver.

## 1. Honest Status

- **What works:** DXVK D3D11 Feature Level 11_0 (`0xb000`, `HRESULT=0x00000000`) is proven via DXVK Native v3.1.1 running in an Alpine glibc chroot on Mali-G615 MC6 (Poco X6 Pro / MT6897). Both D3D11 and D3D9 draw workloads pass.
- **GPU implementation:** Every feature below runs directly on the GPU without CPU fallback or simulation:
  - `geometryShader`: VS/GS executed as compute on the GPU pre-raster path.
  - `tessellationShader`: VS, TCS, tessellator, and TES executed as compute on the GPU pre-raster path.
  - `VK_EXT_transform_feedback`: GPU capture kernel supporting 4 streams, counters, and queries.
  - `textureCompressionBC`: GPU compute shader decode of BC1–BC7 (G615 lacks hardware BC).
  - `shaderClipDistance`, `shaderCullDistance`, `multiViewport` (16 viewports), `fillModeNonSolid`, and `pipelineStatisticsQuery`.
- **Wine path:** **Untested**. Running Windows x86_64 binaries under Wine via Box64 or FEX in the Alpine chroot is an open milestone ([`worklogs/g615-dxvk/PROGRESS.md`](file:///home/abhaybyte/repos/panvk/worklogs/g615-dxvk/PROGRESS.md)).
- **D3D12 (vkd3d-proton):** Blocked. `robustImageAccess2` missing is a known device-creation requirement; native vkd3d smoke not yet run.
- **Known open issues:**
  - **X11 present teardown hang:** DXVK Native `destroySwapchain` deadlocks in `x11_wait_for_present` under X11/Xvfb (hang observed under Xvfb; rate unknown; uncommitted debug logging in `work/mesa-present`).
  - **Intermittent DeviceLost:** 2 sporadic `VK_ERROR_DEVICE_LOST` failures occur in `transform_feedback.*.query_copy_*`.
  - **FL12_0 sparse:** Requires sparse binding, which is a verified `NO-GO` on kbase UAPI 1.21 ([`docs/KBASE-SPARSE-FEASIBILITY.md`](file:///home/abhaybyte/repos/panvk/docs/KBASE-SPARSE-FEASIBILITY.md)).
  - **FL11_1 features:** Missing `vertexPipelineStoresAndAtomics` and `VK_EXT_primitives_generated_query`.

## 2. Prerequisites

- **Reference Device:** Poco X6 Pro (`duchamp`, 2311DRK48I), MediaTek Dimensity 8300-Ultra (MT6897), Mali-G615 MC6 (`0xb8a31030`), CSF frontend, CSF UAPI 1.21.
- **Kernel Interface:** `/dev/mali0` via `mali_kbase`.
  - App-UID access to `/dev/mali0` succeeds without root for standard ioctls, memory allocation, and command submission.
  - **Root requirement:** Export requires accessible `/dev/sw_sync`; else `VK_ERROR_OUT_OF_HOST_MEMORY`. App-UID access is unverified (**untested**). Root or PRoot is also required for the Option B chroot environment.
- **Build Host:** Linux x86_64 machine ([`scripts/build-android.sh`](file:///home/abhaybyte/repos/panvk/scripts/build-android.sh) expects NDK prebuilt `linux-x86_64`; aarch64 hosts need adapted tooling).
  - Required tools: `ccache`, `ninja`, `git`, `meson`, `python3`, `clang`.
  - Android NDK: Installed under `$ANDROID_NDK_ROOT` or `/opt/android-sdk/ndk/` (targeting API 35 with `aarch64-linux-android35-clang`).
  - Host codegen binaries: `mesa_clc` and `vtn_bindgen2` (see [`scripts/bootstrap-host-tools.sh`](file:///home/abhaybyte/repos/panvk/scripts/bootstrap-host-tools.sh); ensure codegen binaries are reachable by [`scripts/build-android.sh`](file:///home/abhaybyte/repos/panvk/scripts/build-android.sh)).

## 3. Build PanVK

Execute commands from the repository root.

### Step 1: Fetch Mesa source
Clone and checkout the exact pinned Mesa commit from `sources.lock`:
```sh
./scripts/fetch-mesa.sh
```

### Step 2: Apply patches
Apply the qualified patch series for the G615 profile:
```sh
./scripts/apply-patches.sh --profile g615-v11-csf
```

### Step 3: Build Android Bionic driver
Build the Bionic `libvulkan_panfrost.so` (targeting Android API 35):
```sh
./scripts/build-android.sh --profile g615-v11-csf
```
*Script options: `--profile g615-v11-csf [--api 35] [--ndk $ANDROID_NDK_ROOT]`.*

### Packaging prerequisites
Both packagers ([`scripts/package-android-adpkg.sh`](file:///home/abhaybyte/repos/panvk/scripts/package-android-adpkg.sh) and [`scripts/package-glibc.sh`](file:///home/abhaybyte/repos/panvk/scripts/package-glibc.sh)) require `dist/extension-gap.json` (generated by extension audit, [`scripts/audit-runtime-extensions.py`](file:///home/abhaybyte/repos/panvk/scripts/audit-runtime-extensions.py)) and validation evidence (collected by [`scripts/collect-validation.py`](file:///home/abhaybyte/repos/panvk/scripts/collect-validation.py) via `generate-release-manifest.py`):
```sh
python3 ./scripts/audit-runtime-extensions.py
```

### Step 4: Package Android adpkg
Create an adrenotools-compatible flat zip for Android frontends (`v0.1.0-beta.3` is frozen and lacks FL11_0 work per [`README.md`](file:///home/abhaybyte/repos/panvk/README.md); use a development version string placeholder e.g. `--version <dev-version>`):
```sh
./scripts/package-android-adpkg.sh --profile g615-v11-csf --version <dev-version>
```
Output: `dist/PanVK-Kbase-Android-g615-v11-csf-<dev-version>-<commit>.adpkg.zip`.

### Step 5: Build glibc driver (for Linux chroot)
Build the native aarch64 glibc ICD and manifest (on non-aarch64 build hosts such as x86_64, this requires a configured device chroot reached via ADB; see [`scripts/build-glibc.sh`](file:///home/abhaybyte/repos/panvk/scripts/build-glibc.sh#L63-L95)):
```sh
./scripts/build-glibc.sh --profile g615-v11-csf --serial "$ANDROID_SERIAL"
```
*Script options: `--profile g615-v11-csf [--serial "$ANDROID_SERIAL"] [--clean] [--jobs 2]`.* Output: `dist/glibc-g615-v11-csf/libvulkan_panfrost.so` and `panfrost_icd.aarch64.json`.

### Step 6: Package glibc zip
Package the glibc ICD for container/chroot environments (`v0.1.0-beta.3` is frozen and lacks FL11_0 work per [`README.md`](file:///home/abhaybyte/repos/panvk/README.md); use `--version <dev-version>`):
```sh
./scripts/package-glibc.sh --profile g615-v11-csf --version <dev-version>
```
Output: `dist/PanVK-Kbase-g615-v11-csf-<dev-version>-<commit>-EMULATOR.zip`.

## 4. Option A: Existing Frontends (Custom Driver ZIP)

Frontends such as StevenMXZ Winlator-Ludashi, TripleJ160 Winlator-Ludashi-Plus, The412Banner Bannerlator, and utkarshdalal GameNative load custom Vulkan drivers via libadrenotools.

### Real Execution Chain

This is the wrapper route (Ludashi/`bionic-vulkan-wrapper`). Ludashi-Plus DAC uses an AHB swapchain layer; Bannerlator's verified adrenotools use is for its host renderer; guest loading is frontend-specific.

1. **Host loader:** The Android app receives PanVK as an `.adpkg.zip` and extracts `libvulkan_panfrost.so`.
2. **Hook:** The game launcher configures `ADRENOTOOLS_DRIVER_PATH` and `ADRENOTOOLS_DRIVER_NAME=libvulkan_panfrost.so`, triggering `adrenotools_open_libvulkan(..., ADRENOTOOLS_DRIVER_CUSTOM, ...)`.
3. **Guest presentation:**
   - DXVK invokes `winevulkan` -> `winex11.drv` `vkCreateXlibSurfaceKHR`.
   - The surface call hits a wrapper ICD (`bionic-vulkan-wrapper`, Mesa fork via `VK_ICD_FILENAMES=wrapper_icd.aarch64.json`).
   - The wrapper's `wsi_common_x11.c` allocates `AHardwareBuffer` swapchain images, sends buffer handles over the `ANDROID_AHB_SERVER` Unix socket, applies synthetic modifier 1255, and invokes `xcb_dri3_pixmap_from_buffers`.
   - The Java X server receives DRI3 buffers and either composites or performs a direct `ASurfaceTransaction_setBuffer` FLIP to SurfaceControl (`Bannerlator/DisplayX`).
4. **Underlying driver:** The wrapper redirects Vulkan rendering calls to the real custom driver (`libvulkan_panfrost.so`).

### Crucial Caveats & Gaps
- **Untested:** Loading PanVK inside these frontends is **untested**.
- **No ICD JSON:** PanVK's `.adpkg.zip` contains `libvulkan_panfrost.so` and `meta.json`, but **no ICD JSON** manifest.
- **Wrapper mandatory:** PanVK compiled for Android does not implement X11 Xlib surfaces directly; an intermediate wrapper like `bionic-vulkan-wrapper` or DAC layer is required.
- **Presentation route:** Direct PanVK X11 WSI on kbase defaults to MIT-SHM CPU copy; in the wrapper route the wrapper owns AHB/DRI3 presentation.
- **DRI3 untested:** Raw dma-buf DRI3 (`PANVK_KBASE_DRI3=raw|termux` or `WSI_X11_TERMUX=1`) is opt-in and **untested** on kbase.
- **sync_fd permission failure:** Export requires accessible `/dev/sw_sync`; else `VK_ERROR_OUT_OF_HOST_MEMORY`. App-UID access is unverified (**untested**).

## 5. Option B: Chroot (Alpine glibc) + Box64/FEX + Wine + DXVK

In this architecture, an Alpine Linux glibc container runs on the device (via PRoot or rooted chroot), loading the native Linux glibc build of PanVK.

### Configuration
1. Install Box64 or FEX-Emu, Wine x86_64, and Windows DXVK DLLs inside the Alpine glibc environment.
2. Point the Khronos Vulkan loader directly to the PanVK ICD manifest:
   ```sh
   export VK_DRIVER_FILES=/path/to/dist/glibc-g615-v11-csf/panfrost_icd.aarch64.json
   # Or legacy fallback:
   export VK_ICD_FILENAMES=/path/to/dist/glibc-g615-v11-csf/panfrost_icd.aarch64.json
   ```
3. Run the Windows game via Box64/FEX and Wine:
   ```sh
   box64 wine game.exe # untested
   ```

### Status
- **DXVK Native:** **Verified**. Native Linux binaries linking DXVK Native v3.1.1 initialize D3D11 FL 11_0 and execute draw workloads.
- **Wine + Box64/FEX:** **Untested**. Translating Windows D3D11 calls across the Wine/emulator boundary to the PanVK glibc ICD has not yet been validated.

## 6. Confirmed Environment Variables

### (a) Implemented PanVK Controls

| Variable | Values / Examples | Purpose & Behavior |
|---|---|---|
| `PANVK_DEBUG` | `wsi_no_afbc` | Disables PanVK WSI AFBC default, not gralloc's chosen AHB layout (AFBC interop is an untested risk). |
| `PANVK_DEBUG` | `no_bc_emul` | Disable GPU compute shader decode of BC1–BC7 (default is enabled). |
| `PANVK_DEBUG` | `no_gs` | Disable geometry shader emulation on GPU pre-raster path. |
| `PANVK_DEBUG` | `gpu_prerast` | Force GPU pre-rasterization compute pipeline for VS/GS/tess. |
| `PANVK_DEBUG` | `kbase_diag` | Enable diagnostic logging for kbase ioctls and memory mapping. |
| `PANVK_DEBUG` | `no_crc` | Disables render-target CRC checksums. |
| `PANVK_DEBUG` | `no_extended_va_range` | Restrict GPU virtual address allocation to 32-bit / standard range. |
| `PANVK_DEBUG` | `robust_ssbo_vec` | Enable NIR vectorizer for robust SSBO loads. |
| `PANVK_DEBUG` | `sync`, `trace` | Force synchronous execution and submit tracing. |
| `PANVK_KBASE_DRI3` | `raw`, `termux` | Enable raw dma-buf export in X11 DRI3 WSI (bypasses default MIT-SHM). |
| `WSI_X11_TERMUX` | `1` | Enable Termux X11 raw-fd DRI3 swapchains. |
| `PANVK_KBASE_GPU_SEMAPHORE_WAITS` | `1`, `true` | Opt in to in-ring GPU semaphore waits for same-queue syncs (leave unset or `false` for default safe CPU-side wait). |
| `PANVK_KBASE_DMA_HEAP` | `/path/to/heap` (default `/dev/dma_heap/system`) | Heap device path for dma-buf heap allocator for kbase buffer export (see [`kbase_kmod.c`](file:///home/abhaybyte/repos/panvk/patches/kbase-common/files/src/panfrost/lib/kmod/kbase_kmod.c#L1281-L1287)). |
| `PANVK_KBASE_HEAP_RENEW_INTERVAL` | `128` (default), `0` (disable) | Interval (in submit batches) to renew CSF tiler heap; `0` disables interval-based renewal (see [`panvk_vX_gpu_queue.c`](file:///home/abhaybyte/repos/panvk/work/mesa-dxint/src/panfrost/vulkan/csf/panvk_vX_gpu_queue.c#L79-L107)). |
| `PANVK_KBASE_HEAP_RENEW_WORK` | `65536` (default) | Separately controls work-based threshold for CSF tiler heap renewal (see [`panvk_vX_gpu_queue.c`](file:///home/abhaybyte/repos/panvk/work/mesa-dxint/src/panfrost/vulkan/csf/panvk_vX_gpu_queue.c#L79-L107)). |

## 7. Troubleshooting

- **Device lost (`VK_ERROR_DEVICE_LOST`):**
  - Transform feedback query copies trigger intermittent device losses (`transform_feedback.*.query_copy_*`).
  - Tiler heap exhaustion on complex geometry: Adjust `PANVK_KBASE_HEAP_RENEW_INTERVAL` or `PANVK_KBASE_HEAP_RENEW_WORK`.
  - Queue submission hangs: Leave `PANVK_KBASE_GPU_SEMAPHORE_WAITS` unset/false (default off) to revert to safe CPU-side synchronization.
- **Red / blue color swap:**
  - Do not apply global R/B swap hacks in driver shaders.
  - Cause: DXVK prefers `VK_FORMAT_B8G8R8A8_UNORM`, whereas Android presentation surfaces expect RGBA.
  - Fix: Handled on the frontend side (StevenMXZ Winlator-Ludashi v3.1.h explicitly fixed Mali color swapping). Frontends must swizzle channels in the presentation layer.
- **Black screen:**
  - Surface format rejected by Android SurfaceFlinger or X server.
  - AFBC modifier mismatch: AFBC interop is an untested risk; `PANVK_DEBUG=wsi_no_afbc` disables PanVK WSI AFBC default, not gralloc's chosen AHB layout.
- **Present hang at application exit:**
  - DXVK Native `destroySwapchain` deadlocks inside `x11_wait_for_present` under X11/Xvfb (hang observed under Xvfb; rate unknown). Teardown waits in `x11_wait_for_present`; root cause unknown, tracing pending; terminate the process manually.
- **Slow presentation / low FPS:**
  - Default X11 WSI on kbase uses MIT-SHM CPU copies (`sw_device=true`).
  - Native Android swapchain (`VK_KHR_android_surface`, patch 016) executes `DeviceWaitIdle` followed by CPU memcpy from AHB to ANativeWindow.
  - Zero-copy direct AHB scanout or working raw DRI3 dma-buf are proposed presentation optimizations; performance on G615 unverified.

## 8. Known Limitations

| Component / Feature | Status | Details & Root Cause |
|---|:---:|---|
| D3D11 Feature Level 11_0 | Working | Verified via DXVK Native v3.1.1 on G615; geometry, tessellation, BC decode run on GPU. |
| D3D11 Feature Level 11_1 | Incomplete | Blocked by missing `vertexPipelineStoresAndAtomics` and primitive query extensions. |
| D3D12 (vkd3d-proton) | Blocked | `robustImageAccess2` missing is a known device-creation requirement; native vkd3d smoke not yet run. |
| D3D12 Feature Level 12_0 | NO-GO | Requires sparse memory binding; impossible on kbase UAPI 1.21. |
| Wine x86_64 Translation | **Untested** | Wine under Box64/FEX in Alpine chroot not yet validated on target. |
| Frontend Driver Loading | **Untested** | `.adpkg.zip` lacks ICD JSON; needs wrapper; `/dev/sw_sync` denied to non-root apps. |
| X11 Presentation | Degraded | Defaults to MIT-SHM CPU copies; teardown hang in `x11_wait_for_present` observed under Xvfb (rate unknown). |
| Native Android Surface WSI | CPU Copy | Patch 016 uses `DeviceWaitIdle` + CPU memcpy; no zero-copy presentation. |
| sync_fd Export | Restricted | Export requires accessible `/dev/sw_sync`; else `VK_ERROR_OUT_OF_HOST_MEMORY`. App-UID access is unverified (**untested**). |
| BC Texture Decompression | Emulated | G615 hardware lacks BCn; emulated via compute shader decode. |

## 9. How to Report Bugs

When submitting bug reports or failure logs, provide all of the following:

1. **Hardware & OS identification:**
   - Phone model (e.g. Poco X6 Pro / `duchamp`) and SoC (MediaTek Dimensity 8300-Ultra / MT6897).
   - Exact GPU ID string from probe or `vulkaninfo` (e.g. `Mali-G615 6 cores r1p3 0xB8A3`).
   - Android build fingerprint: `getprop ro.build.fingerprint`.
   - Execution context: app UID, rooted vs non-root, SELinux enforcing vs permissive.
2. **Driver provenance:**
   - Profile ID: `g615-v11-csf`.
   - Mesa source commit: `git -C work/mesa rev-parse HEAD` (or commit from `sources.lock`).
   - Patch series ID: run `python3 scripts/compute-patch-series-id.py --profile g615-v11-csf`.
3. **Frontend & stack details:**
   - Frontend and version (e.g. Winlator-Ludashi 3.1.h, Bannerlator, NativeCode).
   - Wrapper name and version (e.g. `bionic-vulkan-wrapper`, Wrapper original).
   - Translator versions: Box64 / FEX version, Wine version, DXVK version.
4. **Logs:**
   - DXVK log files: `<game>_d3d11.log` and `<game>_dxgi.log`.
   - Android logcat: `logcat -d | grep -iE 'vulkan|panvk|adrenotools|mesa'`.
   - Kernel dmesg: `dmesg | grep -iE 'mali|kbase'`.
   - Validation output: include `vulkaninfo` output or reproduction script.
